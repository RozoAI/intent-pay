# CI — Chainwright E2E on GitHub Actions

How the real-funds RozoPay E2E suite runs in GitHub Actions: what it needs, how
to set it up, and how to replicate it in another repo.

> ⚠️ **These tests spend real mainnet funds on every run.** They are deliberately
> **not** a pull-request gate. Read the [Security model](#security-model) before
> wiring secrets.

The workflow lives at [`.github/workflows/e2e-chainwright.yml`](../../.github/workflows/e2e-chainwright.yml).

---

## 1. Requirements

| Requirement | Detail |
| --- | --- |
| Runner | `ubuntu-22.04` (matches Chainwright's own CI). `ubuntu-latest` works but pin to 22.04. |
| Display | `xvfb` — browser **extensions don't load in headless Chromium**, so real-funds projects run headed and need a virtual framebuffer. |
| Node / pnpm | Node 22 + pnpm (repo pins `pnpm@11`; `pnpm/action-setup@v4` reads `packageManager`). |
| Playwright | Chromium browser (`playwright install --with-deps chromium`). |
| Chainwright cache | A `setup-wallets` step **before** tests — imports seed phrases into cached wallet profiles. |
| Secrets | 1 EVM seed + 1 Solana seed + 1 Stellar secret + 3 destination addresses (+ merchant app id). |
| Funded wallets | Throwaway wallets holding small real balances — see [§6](#6-funded-wallet-requirements). |
| Job timeout | Up to **360 min** (GitHub-hosted runner hard cap). |

**Not required:** Foundry/anvil. The suite targets mainnet directly; Chainwright's
reference CI installs Foundry, but this repo never uses a local chain.

---

## 2. Why a dedicated workflow (not the shared `fe-gate`)

`fe-gate` is the every-PR frontend gate and cannot host this run:

| Need | `fe-gate` reality |
| --- | --- |
| `xvfb-run` for a headed browser | Installs Chromium `--with-deps`, no xvfb. |
| Chainwright cache-build step | No hook for a pre-test setup step. |
| Seed-phrase secrets | Its only secret is a single `NEXT_PUBLIC_*` dotenv blob. |
| > 20 min runtime | `timeout-minutes: 20`. |

So `e2e-chainwright.yml` is a separate, self-contained workflow. `fe-gate`
keeps running the fast, secret-free `test:pages` screenshots.

---

## 3. Workflow anatomy

Steps, in order:

1. **checkout** — `actions/checkout@v4`.
2. **pnpm / Node** — `pnpm/action-setup@v4` → `actions/setup-node@v4` with `cache: pnpm`.
3. **Install** — `pnpm install --frozen-lockfile`.
4. **xvfb** — `sudo apt-get update && sudo apt-get install -y xvfb`.
5. **Browsers** — `pnpm --filter examples/nextjs-app exec playwright install --with-deps chromium`.
6. **Write `.env.e2e`** — from repo secrets, into `examples/nextjs-app/.env.e2e` (gitignored).
7. **Build wallet cache** — `xvfb-run -a pnpm run setup-wallets` in `examples/nextjs-app`. **Skipped for `scope: mocked`** (no secrets → `setup-wallets` onboarding would fail).
8. **Run** — `xvfb-run -a pnpm test:e2e` (or a subset), in `examples/nextjs-app`. Subset scopes keep going past a failing flow and fail the step at the end.
9. **Upload report** — `on failure`, `playwright-report/` only (never `test-results/`), 1-day retention.
10. **Scrub wallet cache** — `always()`, remove `.wallet-cache/` + `test-results/` (holds imported seeds / traces).

Job-level env that the config depends on:

```yaml
env:
  CI: "1"
  E2E_START_SERVER: "1"          # playwright.config.ts boots `pnpm dev` for you
  BASE_URL: "http://localhost:3000"
```

> `E2E_START_SERVER=1` is **required in CI** — without it the `webServer` block is
> `undefined` and the tests hit an app that was never started.

## 4. Triggers

```yaml
on:
  workflow_dispatch:
    inputs:
      scope:
        type: choice
        default: full
        options: [full, mocked, bridge, checkout, merchant, deposit]
  schedule:
    - cron: "0 18 * * *"   # 01:00 WIB — full matrix nightly
```

- **Never** `pull_request`: real funds + secrets, and fork PRs get no secrets.
- **`concurrency`** is a single static group with `cancel-in-progress: false`:
  concurrent runs draw from the **same source wallets** and would collide on
  nonces / balances. Let one finish.

Run manually from **Actions → e2e-chainwright → Run workflow** and pick a scope:

| Scope | What runs |
| --- | --- |
| `full` | mocked + every real-funds project, in config dependency order |
| `mocked` | fast, secret-free suite only (no real funds) |
| `bridge` / `checkout` / `merchant` / `deposit` | one group, each project via `--no-deps` |

## 5. Setup

### 5.1 Add secrets

**Settings → Secrets and variables → Actions → Secrets**

| Secret | What |
| --- | --- |
| `E2E_EVM_SEED_PHRASE` | MetaMask recovery phrase (EVM source + destination address). |
| `E2E_EVM_WALLET_PASSWORD` | Local-only profile password (any string). |
| `E2E_EVM_ADDRESS` | The EVM wallet's public address — destination for `*-to-evm` flows. |
| `E2E_STELLAR_SECRET` | Stellar `S...` secret — signs when Stellar is source. |
| `E2E_STELLAR_ADDRESS` | Stellar `G...` address — destination for `*-to-stellar` flows. |
| `E2E_SOLANA_SEED_PHRASE` | Phantom recovery phrase (Solana source). |
| `E2E_SOLANA_WALLET_PASSWORD` | Local-only Phantom profile password. |
| `E2E_SOLANA_ADDRESS` | Solana address — destination for `*-to-solana` flows. |
| `E2E_MERCHANT_APP_ID` | Merchant app id for the `merchant-*` / pay-to-address specs (optional; those specs self-skip without it). |

### 5.2 Optional variable

**Settings → Secrets and variables → Actions → Variables**

| Variable | Default | What |
| --- | --- | --- |
| `E2E_AMOUNT` | `0.02` | USDC amount (human units) sent per flow. |

### 5.3 The generated `.env.e2e`

The `Write .env.e2e` step reproduces [`examples/nextjs-app/.env.e2e.example`](../../examples/nextjs-app/.env.e2e.example)
from the secrets. It is written at run time and never committed
(`.env.e2e` is gitignored).

## 6. Funded wallet requirements

Each wallet is **reused across flows** — a source one way, a destination the
other. Fund them with small test amounts only.

| Wallet | Needs |
| --- | --- |
| EVM (MetaMask) | USDC on Base (default source token), plus native gas. Native-source flows use ETH on Ethereum. |
| Solana (Phantom) | USDC on Solana mainnet, plus SOL for fees. Native-source flows use SOL. |
| Stellar | Funds + a **USDC trustline** on the `S...` account (trustline also required on the `G...` destination). |

`E2E_EVM_SOURCE_OPTION_ID` / `E2E_SOLANA_SOURCE_OPTION_ID` can override the
default source token; both default to USDC.

## 7. Security model

1. **Secrets** are stored as GitHub Actions secrets and written to a gitignored
   `.env.e2e`. GitHub masks them in logs.
2. **Wallet cache is never persisted.** `.wallet-cache/<wallet>/<profile>` holds
   the *imported seed phrases*. It is built fresh each run and deliberately
   **not** cached with `actions/cache` — a persisted cache artifact would leak
   the seeds.
3. **Artifacts can contain secrets.** A Playwright **trace embeds page state**,
   which for the Stellar flows includes the injected secret key, and the
   always-on video records every run. The upload therefore **excludes
   `test-results/`** (traces, videos, failure screenshots) and ships only the
   HTML report, keeps `retention-days: 1`, and a final `always()` step wipes
   `.wallet-cache/` and `test-results/`. This is a mechanical guard rather than
   a manual download-and-delete.
4. **`gitleaks`** rules already exist for Stellar seeds, EVM private keys,
   mnemonics, and Supabase service-role keys (see `.github/gitleaks.toml` and the
   secret-scan workflow). Keep them — they are the backstop against a committed
   secret.
5. **Rotate** the throwaway wallets between environments; never reuse a personal
   seed.

## 8. Cost & runtime

- The full matrix is **one linear `dependencies` chain** (mocked → bridge →
  checkout → merchant → deposit), 39 projects, up to 10 min each, run
  sequentially (`workers: 1`).
- Worst case exceeds the **360-minute** GitHub cap. If that happens:
  - run a `scope` subset manually, or
  - alternate the nightly job across two nights (e.g. `bridge,checkout` then
    `merchant,deposit`), or
  - split by **disjoint wallet sets** — never by flow group alone, because the
    same wallets are reused everywhere and parallel draws cause nonce races.

## 9. Troubleshooting CI-specific failures

| Symptom | Cause / fix |
| --- | --- |
| `Target page, context or browser has been closed` right after launch | Missing xvfb / headed browser with no display. Confirm the step wraps in `xvfb-run`. |
| Extensions never appear | Chromium ran headless. Real-funds projects set `headless: false` and must run under xvfb. |
| Tests fail connecting to `http://localhost:3000` | `E2E_START_SERVER` not set, so the `webServer` never started. |
| `❌ E2E environment is not fully configured` | `globalSetup` blocked a real-funds run — a secret is missing/empty. Set all six, or use `scope: mocked` (`SKIP_ENV_VALIDATION=1`). |
| All real-funds specs report "skipped" | Their secret env var is absent (specs self-skip). Check the secret names exactly. |
| Wallet setup hangs or times out | `setup-wallets` needs a display too — it must run under `xvfb-run`, and cwd must be `examples/nextjs-app` (the cache path is resolved from `process.cwd()`). |
| Job killed at 360 min | Full matrix too long — see [§8](#8-cost--runtime). |

## 10. Replicating this in another repo

Checklist:

1. Add `chainwright` + `@playwright/test` as dev deps; add `e2e/wallet-setup/*.setup.ts`.
2. Add `.env.e2e.example` (committed) and gitignore `.env.e2e` and `.wallet-cache/`.
3. Copy `.github/workflows/e2e-chainwright.yml`; keep steps 4–8 (xvfb → browsers →
   env → cache-build → run) unchanged.
4. Point `working-directory` / `--filter` at your app package.
5. Set the secrets; fund the wallets.
6. Verify locally first (`pnpm setup-wallets` then a single `--no-deps` flow),
   then run a manual `scope: bridge` (or equivalent) before enabling the nightly.

The `wallet-cancel` project drives MetaMask/Phantom to the confirmation popup and
cancels — covering amount, user-cancel, retry and insufficient-balance cases
without spending. It is **not** part of this workflow's nightly full scope (which
spends real funds). See [13-negative-and-cancel.md](./13-negative-and-cancel.md).

## 12. Known limitations

- No parallel sharding (shared wallets — see §3/§8).
- Full matrix may not fit the 6-hour cap.
- Failure artifacts may embed the Stellar secret (traces).
- `merchant-*` and pay-to-address specs self-skip unless `E2E_MERCHANT_APP_ID`
  is set.
